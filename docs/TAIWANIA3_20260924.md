## 下載更新、檢查、提交第一個案例

```bash
cd /work/dawson666/src/nano_tensile_TFvW_20260924
git pull --ff-only origin codex/portable-qe-20260923
bash hpc/taiwania3_qe.sh check
```

只有最後出現 `[CHECK COMPLETE]` 才表示這些前置檢查通過。任何 module、library、路徑或排程錯誤都會停止，不會自動改用另一個 QE 或另一個計畫。此指令不會開始計算。

確認帳號仍有額度與個人儲存空間（站方 `wallet` / `get_su_balance` 與可用的 quota 工具／iService HFS 頁面），再提交一個 1NN 作業：

```bash
bash hpc/taiwania3_qe.sh submit 2V_1NN_D110
squeue -u dawson666
```

`submit` 會再次檢查，再透過 Slurm 真正提交一個作業。記錄 `[SUBMITTED] job=...`；這僅代表進入排程，不代表開始或完成。相同名稱已排隊／執行時 helper 會拒絕重複提交；這是提交前檢查，仍應避免兩個終端同時提交，執行階段另有 case lock。輸出在：

```text
/work/dawson666/qe_cases/qe_runs/AL_DIVACANCY_SCF_20260924/
    slurm-logs/                     排程 stdout/stderr、提交清單
    2V_1NN_D110/<unique-attempt>/   原始輸出、精確輸入、狀態、scratch
```

第一個作業沿用舊腳本的 1 node、29 MPI ranks、每 rank 1 thread、64 GB；時限先設 12 小時，QE 11 小時後要求正常停止。這是有來源的初始資源設定，尚未證明最省資源或一定足夠。`max_seconds` 不保證瞬間結束，也不保證當次 SCF 會完成。不在這一輪調整 k-point pools 或其他平行參數。

專用 `taiwania3_qe.sbatch` 在計算節點重新載入 modules 與 PMI，再呼叫 generic template 設定 OpenMP／BLAS 執行緒及啟動 portable runner。每次前置檢查保存 QE binary SHA-256、腳本 SHA-256、Git commit、module 與函式庫紀錄；提交清單連到該紀錄。若 checkout 已有 `env/local-qe.sh`，helper 會停止，避免第二份環境初始化改掉此 Intel profile。可使用 `QE_ACCOUNT`、`QE_PARTITION`、`QE_BINARY`、`QE_PYTHON`、`QE_WORK_ROOT`、`QE_PMI_LIBRARY` 明確覆寫預設值；不能靠改環境變數調整 29 ranks／12 小時而不一起修改完整 profile。

## 為何先重算已做過的 1NN

保存的本機參考用 QE 7.5，本次已改採使用者提供的國網 QE 7.5 路徑。仍先在國網重算 1NN，留下同一 QE binary／MPI／資源配置的基準，再以同一環境算其他三個構型。版本字串相同不保證編譯環境相同，因此不能省略同站參考查核。collector 能拒絕不同 QE 版本，但沒有辨識所有同版本不同 build 的能力；國網 1NN 完成前，不將 collector 採用的舊本機參考誤稱為同站驗證。

1NN 確認執行與收斂後，接續 `2V_2NN_D100`、`2V_D310_r1`、`2V_D110_r2`。各 case 不同，但科學條件不變：106 原子、固定 TFvW 鬆弛後幾何、LDA、相同 UPF、60/240 Ry、3×3×3 k points、MV 0.02 Ry、200 bands、SCF 門檻 1e-9 Ry。所有改變都需要新的可辨識 protocol。
